# Devlog — v1.3.x CI/CD and supply chain

Brought this repo's CI/CD up to what `../gogdl-lib` runs since its own CI/CD line
(`../gogdl-lib/devlog/v1.2.x-ci-cd.md`), adapted to a Flutter + Rust bridge, plus a public push mirror
to GitHub, ending with `main` and the `v*` tags protected. Ran as steps 0–18 of a work plan (deleted
with this devlog) over seven squash MRs, several of which merged early and continued on a fresh branch
(1/1b/1c, 2/2b/2c/2d). Two releases came out of it: `v1.3.1` (rustls 0.23.45, RUSTSEC-2026-0285) and
`v1.3.2` (same code, a working `release` job). SHAs below are the commits on `main`. Kept here for the
decisions and pitfalls that aren't obvious from the diff.

## Step 0 — Decisions

- **D1 merge method:** as the lib: fast-forward with squash required, squash message = MR title,
  source branch deleted.
- **D2 tags:** on `main`, after the release MR merges. Lumen needing unreleased work pins `ref:` to a
  commit on its own feature branch.
- **D3 runner load:** heavier than the lib (`integration` builds the Linux app, `codegen` and `rust`
  each compile the crate). Accepted with `interruptible` and auto-cancel. Fallback: `integration`
  manual on MRs. Not measured.
- **D4 toolchain bumps:** the CI image is shared with Lumen, so Flutter, Rust and frb move by hand,
  together, in both repos. Renovate ignores all three. This differs from the lib, where Renovate opens
  the bump and the red `.toolchain` check is the reminder.
- **D5 Renovate and releases:** `update-lockfile` for cargo and pub. Unlike the lib, this repo's
  `rust/Cargo.lock` is what Lumen builds, so a lock update reaches Lumen at the next tag: a security fix
  gets its own patch tag, routine updates ride along with the next release. `gogdl-lib` is ignored:
  a pin bump is an API change, done by hand.
- **D6 mirror and license:** public, `fernando-navarrete/gogdl_flutter` (the name Lumen's `insteadOf`
  expects), `MIT OR Apache-2.0` as the lib.
- **D7 mirror push:** GitLab's built-in push mirror, so no CI job gets the token. Lumen's B2 asked for
  a mirror job that checks the pinned `gogdl-lib` tag is on GitHub; that check lives in `release`
  instead, which runs before anyone can pin the tag.
- **D8 lint scope:** unchanged (fmt, clippy `-D warnings`, `analyze --fatal-infos`), `cargo deny` as
  its own job, no `dart format` gate.
- **D9 downstream job:** not now. Lumen already scans this repo's `Cargo.lock` (`bridge-lock`), and a
  breaking change ships with Lumen's adopting MR anyway.
- **D10 `gogdl-lib` URL:** `rust/Cargo.toml` keeps `ssh://git@thinkcentre.home:2200`. SHAs match
  across the mirror, and outside the LAN an `insteadOf` rewrite points it at GitHub.

**Blocker B1 (in gogdl-lib):** its GitHub `v1.2.3` was at `51075b0`, a throwaway commit from its tag
bite test: GitLab had been restored, but GitHub's no-bypass ruleset rejected the mirror's restore.
Fixed by turning the `v*` ruleset off for one "Update now"; every GitHub ref then matched GitLab.

## Steps 1–4 — MR pipelines, hook, pinned images, release flow (`1edda62`, `3f2bb18`, `c9e48b2`)

- `workflow:rules` from the lib: MRs, `main`, `vX.Y.Z` tags, web runs and schedules; a branch with an
  open MR runs only the MR pipeline, one without runs nothing.
- Pre-commit hook: `cargo fmt --check` in `rust/`, checks only.
- The image pins `debian:bookworm-slim` and `release-cli` by digest and `rustup-init` by sha256, as the
  lib. Flutter is cloned by tag, then `git rev-parse HEAD` must equal the `FLUTTER_COMMIT` that
  `ci/build-image.sh` passes in, so a moved tag fails the build. Image revisions (`-rN`) let both
  `-r` tags sit on the runner host: Lumen kept its old tag until its own MR.
- `release` needs every check job, fetches with `GIT_DEPTH: 0`, and fails unless the tagged commit is
  an ancestor of `origin/main`.

**Pitfall:** the squash message was the branch's first commit message, not the MR title ("Add the
CI/CD work plan" for MR 1, "CI: pre-commit hook" for MR 1b). Setting the squash template to
`%{title}` (step 5) wasn't enough: GitLab titles a new MR from its first commit, and the template copies
that, so `5478d80` and `f1d7b93` carry plan-commit messages too. Set the MR title explicitly when
opening it, and check the squash message in the merge widget before merging.

## Step 5 — Protect `main` and `v*` (settings)

Done right after MR 1c, not last as in the lib, because of two of its pitfalls: protected variables
reach only protected refs (Renovate's tokens), and a tag bite test run before `v*` is protected really
moves the tag. Bite tests: a direct push to `main` is rejected; an MR with a panicking test (!4) has no
Merge button; `git push --delete origin v1.3.0` is rejected, though a Maintainer can still delete a tag
from the web UI. No force-move test. Every ref matched the pre-test baseline afterwards.

## Step 6 — `cargo-deny` (`5478d80`)

`allow-git` lists only the `gogdl-lib` URL. The first local run found four things, all fixed by
semver-compatible lock bumps to versions over 7 days old: RUSTSEC-2026-0285 (`rustls` 0.23.43 →
0.23.45), RUSTSEC-2026-0190 unsound (`anyhow` → 1.0.104), RUSTSEC-2025-0056 unmaintained `adler`
(`backtrace` → 0.3.76, which moves to `adler2`), and the rejected `Unicode-DFS-2016` (`unicode-ident` →
1.0.26). The last three come in through frb's `allo-isolate`. `gogdl-lib` `v1.2.3` predates its
`license` field, so a `[[licenses.clarify]]` covers it until the pin moves. Bite test: `main`'s old
lock in !6 turned `audit` red.

## Steps 7–8 — pub lockfile check, OSV-Scanner (`f1d7b93`)

- `tool/check_lockfile.sh` (from Lumen) only checks that each package is from pub.dev with a `sha256`,
  an SDK package, or the `path: ".."` bridge. What catches a hand-edited hash is
  `flutter pub get --enforce-lockfile`, even with a warm cache (!7). Both `dart` and `integration` use it.
- `scan` runs the scanner twice, once per lock file, so the exit code splits cargo from pub without
  jq. Cargo fails only on `MAL-` ids (`audit` gates the rest); pub fails on any advisory, since nothing
  else gates pub. The "Weekly scan" schedule runs exactly `audit` and `scan`.

## Steps 9–11 — Secrets, `SECURITY.md`, `v1.3.1` and `v1.3.2` (`50c48f2`, `2ee9b4f`)

- Full-history gitleaks before the mirror: 155 commits, every ref and tag, no findings, so
  `.gitleaks.toml` has no allowlist. Bite test: a fake `ghp_` token in !10 turned `secrets` red.
- `SECURITY.md` covers pub packages as well as crates, and notes that `hook/build.dart` runs cargo in
  every consuming app's build: a `build.rs` here runs on Lumen's machines and CI (64 crates have a
  `build.rs` or proc macro).

**Pitfall:** `v1.3.1`'s check jobs were green but `release` failed: its `git fetch` of `main` ran
before the step that adds the runner's private CA, so git hit "self-signed certificate". A tag
pipeline runs the tagged commit's `.gitlab-ci.yml`, so a retry can't pick up a fix. `v1.3.1` stands
with no GitLab release, and `v1.3.2` (same code, CA step first) was the first green run of the `needs`
+ on-`main` release in either repo. gogdl-lib had the same order and took the same fix.

## Steps 12–13 — Renovate (`bec544e`, first MR `faec192`)

- `ci/Dockerfile`'s base digest has its own group (`ci image base`): that MR needs an image rebuild
  and a new `image:` in both repos, and would otherwise hold up the grouped MR.
- `constraints` pin the Rust and Flutter that Renovate installs to run cargo and pub; they move with
  the toolchains.
- Renovate passes its child processes only a few variables, so no ssh-agent: the `gogdl-lib` deploy key
  goes in `~/.ssh/config`, and `~/.cargo/config.toml` sets `git-fetch-with-cli` (cargo's built-in git
  only uses the agent). A guard fails the job when Renovate aborts (from Lumen).
- The first live run, started from the Dependency Dashboard, merged as `faec192` (`reqwest` 0.13.5,
  `thiserror` 2.0.21; the checkbox skips the schedule, not `minimumReleaseAge`). Bite test in !14:
  both tokens print empty on an unprotected branch, with and without `environment: renovate`, while
  the unprotected deploy key prints as set. The dry run and calendar reminders weren't recorded.

## Steps 14–17 — GitHub mirror (`4303170`)

- `LICENSE-MIT` and `LICENSE-APACHE`, and `deny.toml` stops ignoring this crate's own license, so
  `audit` checks it (red with `GPL-3.0-only` on a scratch copy). With SSH disabled and only the
  README's `insteadOf` line, cargo fetched `gogdl-lib` from its GitHub mirror at the locked SHA.
- **Decision:** the GitHub rulesets on `main` and `v*` (no deletion, no force push) bypass for the
  Repository admin role. On a personal repo a fine-grained token acts as the owner, so that is the only
  bypass that lets the mirror push a restore, which gogdl-lib's no-bypass ruleset couldn't (B1). The
  cost: the ruleset doesn't stop the owner or the token from moving a tag on GitHub. GitLab's `v*`
  protection is the real guard, and an `ls-remote` comparison of both sides is the check.
- After the first "Update now", GitHub had `main` and all 45 tags (the old `-restart`/`-debug` ones
  match `v*` too), every one at its GitLab SHA, and no other branch. The `4303170` merge reached GitHub
  on its own.
- `tool/check_lib_pin.sh`, run by `release` after the on-`main` check, reads the `gogdl-lib` tag and
  SHA from `rust/Cargo.lock` and fails unless GitHub has that tag at that SHA (peeled `^{}` when
  annotated). This is Lumen's B2/B4: a bridge tag never pins a dependency GitHub doesn't have. Red
  cases tested locally: a wrong SHA, a missing tag, a `rev=` pin, no `gogdl-lib` package, an annotated
  tag moved to its parent. Its first real run is the next tag.
