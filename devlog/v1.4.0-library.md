# Devlog — v1.4.0 Library and account

What Lumen's `v1.4.0` library stage needed from the bridge (its D3 `clearCache()` and D1
`removeProducts()`), plus three follow-up patches. Ran as tasks T0–T6 and P1–P3 on 2026-10-12 and
13, one squash MR per task, ending in four tags: `v1.4.0`–`v1.4.3`. **Not breaking**: everything was
added. Every tag pipeline was green, including `release` and `tool/check_lib_pin.sh`'s first real
run. The work plan was deleted with this devlog. Adopting it is Lumen's own Phase 6 (it still pins
`v1.3.3`; it should go straight to `v1.4.3`). Kept here for the decisions and pitfalls that aren't
obvious from the diff.

## T0–T1 — Plan and upstream requests

The plan went straight to `main` (`f441171`), so no MR pipeline ran before T2. Upstream chose D1(b):
`clear_cache` and `remove_products` shipped in its `v1.3.0`, and it dropped `GogDl::logout`, which
nobody needed (GAPS §7.5).

## T2 — Pin `gogdl-lib` `v1.3.2`

Pinned at `8df36d0`. **Pitfall:** `download_game` now skips chunks that are already verified, so the
download counter would have ended short of `started.totalBytes`. `DownloadTranslator` seeds the
counter with the skipped compressed bytes, and `downloadProgress` still reaches 100%.
`GamesError::ProductNotAGame` maps to `notFound`, as `BuildNotFound` did. `OwnedGames.unresolved`
isn't surfaced (GAPS §2). No Dart API diff.

## T3 — `clearCache()`

Async even if upstream's is sync, so it never blocks Dart's isolate on a lock held by a fetch. The doc
comment lists what it clears and what it keeps.

## T4 — `removeProducts()`

`ProductRemoval` follows `install_size.rs` (`non_opaque`, a `from_gogdl` adapter, a unit test built
from the upstream type). Upstream's removal failure (`FileRemovalError`) already mapped to
`fileSystem`, so there's no new `GogErrorKind`, which would have made the release breaking; it got a
test only.

## T5 — End-to-end check

Lumen had no calling code yet, so it ran as a throwaway Dart probe in `example/`, not committed.

- **`removeProducts`**: removing Trauma (`1288586309`) from Alien: Isolation (build `1.0.4`) took
  6.9 s and returned `filesRemoved` 680, `bytesFreed` 1,605,160,642, both equal to what left the disk.
  All 45 `*_FRONTEND.TXT` files (shared with the base game) and a sentinel in the install root
  survived. `repairGame` with the other 7 products downloaded nothing and `verifyDownload` found 0 bad
  chunks. Repairing with all 8 restored the install in 64.6 s.
- **D2 — keep the `Future`.** The time is mostly manifest fetches, it's a one-off behind a confirm,
  and calling it again finishes a partial job.
- **Pitfall — `clearCache()` isn't proven end to end.** The account's new game was a demo, which is in
  `getFilteredProducts` but not in `user/data/games` (what `getOwnedGames` reads), so the owned list
  never changed. The box was ticked on timings (`getGameBuilds` 199 ms, 2 ms cached, 18 ms after the
  clear) and upstream's own test. Re-run it with a full free game.
- **Pitfall:** `ProductRemoval` wasn't exported from `lib/gogdl_flutter.dart`, the same `show`-list
  trap as `v1.3.0`. Fixed in the release MR.

## T6 — Release `v1.4.0`

The first real run of `tool/check_lib_pin.sh` in a tag pipeline was green (GAPS §6).

## P1 — `v1.4.1`: faster, tolerant `getDownloadableProducts`

`resolve_products` fetches details 8 at a time with `buffered` (order kept) behind a closure seam, so
the tests need no network. **D3 = drop a failed DLC, fail the call if the base game's lookup fails**
(the DLC tab means nothing without it). Alien: Isolation went from Lumen's 2.5 s to 755 ms cold.

## P2 — `v1.4.2`: `getGameLinks()`

**Pitfall:** frb 2.13.0 doesn't turn `#[deprecated]` into Dart's `@Deprecated`, so the old getters say
so in their doc comments and the changelog only. `#[deprecated]` also made the generated wrappers
fail `clippy -D warnings`; `mod frb_generated` carries `#[allow(deprecated)]` until the getters go in
`v1.5.0`.

## P3 — `v1.4.3`: Proton pages

`getProtonReleasePage` reports `hasMore` from the unfiltered page size. **Decision:** a negative
`page` fails with a new opaque `GogError::InvalidArgument` (kind `unknown`, so `GogErrorKind` is
unchanged) rather than taking a `u32`, because Dart's codec would still wrap a negative int into one.
Both the old and new methods check it.
